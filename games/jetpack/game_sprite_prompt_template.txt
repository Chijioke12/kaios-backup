SECTION 2 — QUALITY REQUIREMENTS  (paste this block verbatim, never skip it)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

MANDATORY QUALITY RULES — every single sprite must follow all of these:

1. THREE-TONE SHADING
   Every surface must have 3 layers: highlight (top/light edge),
   midtone (main fill), shadow (bottom/dark edge).
   No flat single-color fills anywhere.

2. INK OUTLINE
   Every shape must have a dark outline (1–2px, color: ~(25, 20, 15)).
   This separates elements and gives the art a crisp, finished look.

3. SPECULAR HIGHLIGHTS
   Any rounded, shiny, or metallic surface needs a small bright arc or dot
   to simulate a light reflection. Use d.arc() for curved surfaces.

4. CONSISTENT LIGHT SOURCE
   All sprites share the same light direction: top-left.
   Highlights go on top-left edges. Shadows go on bottom-right edges.

5. ROUNDED CORNERS
   Use rounded_rect() instead of plain rectangle() wherever possible.
   Sharp boxes look unfinished. Radius of 3–6px depending on sprite size.

6. SECONDARY DETAILS
   Every sprite needs at least 2–3 small detail elements beyond the basic
   shape. Examples:
   - Characters: iris + pupil + shine dot in eyes, hair detail, belt/buttons
   - Vehicles/machines: gauge dial, bolts, vents, decals
   - Platforms: surface texture, shine strip, shadow underside
   - Power-ups: inner glow, sparkle points, shine arc
   - Enemies: pupils with shine, texture pattern, expression detail

7. TRANSPARENT RGBA BACKGROUND
   Every sprite must be on a transparent background (0, 0, 0, 0).
   Never use a white or colored background fill.

8. HELPER FUNCTIONS
   Define reusable helpers at the top:
   - rounded_rect(d, x0, y0, x1, y1, r, fill, outline, lw)
   - ellipse(d, x0, y0, x1, y1, fill, outline, lw)
   - poly(d, pts, fill, outline, lw)
   - sprite(w, h)  → returns a blank transparent RGBA image
   - blit(img, ox, oy)  → pastes sprite onto sheet
   - reg(name, x, y, w, h)  → registers sprite in atlas dict

9. VISUAL HIERARCHY
   Each sprite must read clearly at small sizes. The most important element
   (face, logo, glowing core) should be the brightest point.
   Use contrast to guide the eye.

10. COMMERCIAL QUALITY BAR
    The result should look like it belongs in a published indie mobile game —
    not a prototype, not a tutorial placeholder, not clip art.
    If a sprite looks too simple, add more detail until it doesn't.

Structure the Python file exactly like this:

  1. Imports (json, math, PIL)
  2. Sheet size constants (SHEET_W, SHEET_H)
  3. Palette dict P = { "name": (R, G, B, A), ... }
  4. Helper functions (sprite, blit, reg, rounded_rect, ellipse, poly)
  5. One function per sprite: make_[name]() → returns RGBA Image
  6. Layout section: place() calls with x/y coordinates
  7. Save section: write PNG and atlas JSON

Each make_[name]() function must:
  - Create its own blank transparent image with sprite(w, h)
  - Draw everything using P["color_name"] references, never raw RGB tuples
  - Return the finished image
  - Be completely self-contained (no global draw object)

SECTION 4 — ATLAS OUTPUT FORMAT  (paste verbatim)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The atlas JSON must follow the TexturePacker format exactly:

{
  "meta": {
    "image": "[filename].png",
    "size": { "w": SHEET_W, "h": SHEET_H },
    "scale": 1,
    "format": "RGBA"
  },
  "frames": {
    "sprite_name": {
      "frame":            { "x": X, "y": Y, "w": W, "h": H },
      "rotated":          false,
      "trimmed":          false,
      "spriteSourceSize": { "x": 0, "y": 0, "w": W, "h": H },
      "sourceSize":       { "w": W, "h": H }
    }
  }
}

This format is compatible with: Phaser 3, Pixi.js, Unity, Godot, LibGDX.
